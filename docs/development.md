# 开发说明

Python 3.10+，仅标准库。项目负责规则获取、解析、合并、保护、验证及分发。

## 代码结构

| 文件 | 职责 |
| --- | --- |
| `scripts/build.py` | 固定来源、下载、合并、渲染及快照 |
| `scripts/rules/parsers.py` | 严格解析及保留匹配语义的转换 |
| `scripts/rules/protection.py` | 原文索引、全局保护及交集分析 |
| `scripts/validate.py` | 稳定差异、审核报告和候选封存 |
| `scripts/smoke_engines.py` | 固定官方内核、隔离 DNS/HTTP 匹配测试 |
| `scripts/publish_candidate.py` | 候选发布和配套固定版本配置 |
| `scripts/promote.py` | 审核检查、稳定晋升及追加提交回滚 |
| `scripts/check_remote.py` | 固定提交的公开规则哈希核验 |
| `config/`、`tests/` | 来源与策略配置、回归和内核场景 |

处理顺序：固定输入 → 原生解析 → 合并全部来源及本地规则 → 全局保护 → 渲染 → 差异检查 → 内核测试 → 封存 → 审核 → 发布。解析和保护模块不访问网络或发布分支。

## 约定

- 精确域名、后缀、关键字、原生模式、IP 地址族与 `no-resolve` 保留各自语义；未知格式失败。
- 每条规则保留全部来源、原始文件、行号和原文；本地规则也记录位置。先合并后保护，避免其他来源重新引入被剔除的规则。
- 保留 CLI 和订阅文件名，输出稳定排序，gzip 索引固定时间戳。完整源码、配置、场景与许可随快照保存。
- 验证结果绑定规则、源码、配置、场景及内核指纹。候选 ID 不包含自身、运行时间、人工记录或候选提交，避免循环哈希。
- 发布只消费已验证的产物。Mihomo 固定配置在规则提交产生后生成，不能改写已测规则或分流语义。
- 本地检查、受控内核结果、实际使用审核和在线发布分别确认，不将一项结果当作另一项证明。

## 验证

```bash
python3 -m unittest discover -s tests -v
```

回归覆盖来源追溯、解析边界、保护冲突、离线复现、文件安全、证据绑定及临时 Git 发布和回滚。内核检查命令见 [维护说明](maintenance.md)。

集成测试使用临时目录、回环高位端口和受控 DNS/HTTP 服务。保护交集合成样例预期为拦截，用于暴露限制，不证明实际业务安全。缺少内核、必测项或有效证据时不得宣称通过。

生成报告、日志和逐次测试明细不提交到 main；只保留可重复运行的测试和必要场景。
