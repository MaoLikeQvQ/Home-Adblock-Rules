# 开发说明

## 范围与结构

本项目负责规则获取、合并、保护、验证和分发；不负责 DNS 服务安装、路由器固件、代理节点或 App Hook。使用 Python 3.10+ 标准库，内核集成测试另需固定版本的官方可执行文件。

| 文件或目录 | 职责 |
| --- | --- |
| `scripts/build.py` | 固定上游、下载、合并编排、输出及来源快照 |
| `scripts/rules/parsers.py` | 严格解析原生格式和保留语义的转换 |
| `scripts/rules/protection.py` | 全部来源的原文索引、全局保护及交集分析 |
| `scripts/validate.py` | 对照稳定基准分析变化，生成验证报告及封存清单 |
| `scripts/smoke_engines.py` | 固定内核包校验、隔离运行和受控 DNS/HTTP 测试 |
| `scripts/publish_candidate.py` | 发布不可变候选和配套固定版本配置 |
| `scripts/promote.py` | 验收检查、稳定晋升及追加提交回滚 |
| `scripts/check_remote.py` | 固定发布提交的公开规则哈希核验 |
| `config/` | 来源、本地拦截/放行、保护策略、验证阈值及内核版本 |
| `tests/` | 小型构建样例、边界测试、Git 发布模拟和内核场景 |

处理顺序：固定输入 → 原生解析及来源聚合 → 合并全部来源与本地规则 → 全局保护 → 渲染 → 稳定差异检查 → 实际内核验证 → 封存候选 → 审核和设备验收 → 晋升。

解析和保护模块不访问网络或发布分支；入口负责组合。发布工具只消费已经验证的产物，不重新下载或构建规则。

## 数据与兼容约定

- `DOMAIN`、`DOMAIN-SUFFIX`、关键字、原生模式、IP 地址族和 `no-resolve` 分别处理，不以数量一致为由改变语义。未知语法明确失败。
- 相同语义规则聚合全部来源；每条 origin 保存来源 ID、原始文件、1 起始行号及原文。本地规则也保留位置。
- 先合并后保护，防止其他来源重新引入已剔除规则。明确放行不能被广告例外暗中覆盖。
- 保留已有 `build.py` CLI 和订阅文件名。输出采用稳定排序，压缩索引使用固定 gzip 时间，支持离线复现。
- `report.json` 保留来源、数量和规则哈希；`decisions.json` 记录处理原因；`rules.jsonl.gz` 保存完整来源索引。这些都是构建产物，不作为静态文档提交到 main。
- `validation.json` 记录差异、审核项及输入指纹；`engines.json` 记录固定内核和场景结果。通过、失败、待审核、未完成不能混为一谈。
- `manifest.json` 封存文件和参与构建的源码/配置指纹。内容 ID 排除自身、运行时间、人工记录和候选 Git 提交，避免循环哈希。
- 固定提交的 Mihomo 示例在规则提交产生后单独生成；不能修改已测规则，也不能让配置或哈希自引用。

完整源码、配置、场景和许可随发布快照保存，拆分模块时不得只导出旧的单脚本。

## 测试

```bash
python3 -m unittest discover -s tests -v
```

自动回归覆盖来源追溯、语义边界、策略冲突、异常输入、离线复现、文件安全、验证证据绑定及临时 Git 发布/回滚。真实内核检查通过 `scripts/smoke_engines.py` 执行，命令见 [维护指南](maintenance.md)。

集成测试使用临时目录、回环高位端口和受控 DNS/HTTP 服务，不修改系统 DNS。分别记录上游场景、合成边界及保护交集复现。交集样例预期为拦截，用于证明保护限制，不能被描述成业务安全通过。

检查重点：

- 失败保留旧产物，缺内核或必测项不通过，不用公网解析结果代替匹配验证。
- 候选规则、配置、场景、内核版本和稳定基准必须与验证记录一致。
- 候选不可被重新贴上新的稳定基准以绕过差异分析。
- 固定配置须保持分流语义且引用同一批规则；拒绝路径穿越、符号链接和篡改产物。
- 发布模拟只在临时裸仓库执行；不以模拟结果声称真实 GitHub 或路由器验收成功。

测试明细、日志、JSON 结果和一次性核验报告放在本地 `work/`、`artifacts/` 或 Actions 产物，不提交到源码分支。保留可重复执行的测试代码和必要场景。
