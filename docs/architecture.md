# 工程架构

状态：当前架构已核对；目标架构待实施。任务进度统一见 [实施计划](roadmap.md)。

## 项目定位

Home-Adblock-Rules 为个人及家庭设备提供可追溯、可验证、可回退的广告过滤规则。当前接入三个上游项目，产出 Mihomo Classical 与 AdGuard DNS 两类订阅。规则来源可靠、转换范围正确、实际业务可用是三个不同目标，分别提供证据。

工程只负责规则获取、处理、验证与分发。DNS 服务安装、系统网络设置、路由器固件、代理节点、Tailscale 组网和 App Hook 不在本项目范围内。首阶段保持 Python 3.10+ 与标准库，使用 GitHub Actions，无需另建数据库、管理后台或常驻服务。内核测试需要独立的官方可执行文件。

## 当前架构

`scripts/build.py` 同时承担来源固定、下载、解析、去重、本地补充、输出及报告生成。`tests/test_build.py` 覆盖 20 项构建相关测试。工作流构建成功后直接更新 `dist`，没有候选通道。两种实际内核曾在本地验证，尚未进入每次构建的 CI。

```text
config/sources.json + 上游固定提交
                ↓
        build.py 下载、解析、合并
                ↑
config/blocklist.txt + config/allowlist.txt
                ↓
本地 dist/：订阅、原始快照、来源与输出哈希
                ↓
GitHub Actions：构建成功后直接发布 dist 分支
```

现有保护包括必需来源完整获取、未知语法报错、最低条数、来源规则骤减检查及输出失败保留旧文件。它们不能发现所有业务误拦，也没有覆盖上游之间的业务保护策略冲突。

## 目标处理顺序

1. 固定源码、来源配置和上游提交，下载原始文件并记录哈希。
2. 解析为保留匹配语义的规则记录，保存所有来源归属。
3. 合并相同规则与本地补充，保留上游放行规则。
4. 对合并结果应用本项目的业务保护策略，记录每个处理决定。
5. 渲染客户端文件，检查与基准版本的差异及审核项。
6. 静态回归和两种实际内核测试，生成验证清单。
7. 发布候选快照，固定版本试用；通过后晋升同一批字节至稳定通道。

所有规则来源先合并再统一保护，防止一个来源移除的规则被另一个来源重新加入。不同客户端允许输出不同结果；不能为了数量一致而扩大或缩小语义。

## 模块职责与依赖

以下路径为目标目录，尚未创建。按照实际功能逐步拆分，保留现有构建入口；不先创建空模块。

```text
scripts/
  build.py                 构建入口，保持原有命令可用
  validate.py              差异、策略与场景检查入口
  smoke_engines.py          隔离内核验证入口
  promote.py               固定候选晋升与稳定版本回退入口
  rules/
    model.py               规则类型、来源和策略决定的数据结构
    sources.py             固定上游版本、下载与快照
    parsers.py             原生格式解析与语义校验
    merge.py               同语义去重、来源聚合和冲突收集
    protection.py          保护范围和可保留广告例外
    render.py              客户端订阅与配置示例
    reports.py             证据、差异和验证报告
config/
  sources.json             已有：必需上游与数量阈值
  blocklist.txt            已有：手动补充拦截
  allowlist.txt            已有：明确放行
  protection.json          待建：业务保护策略与证据
  validation.json          待建：差异审核阈值、内核版本与哈希
tests/
  scenarios.json           待建：域名、IP、客户端及预期行为
  fixtures/                待建：离线输入、冲突及异常响应样例
```

依赖方向：数据模型供各模块使用；解析器不访问网络；合并和保护不读写发布分支；渲染不修改规则决策；报告消费结果；入口负责组合。发布模块只接受已验证产物，不调用下载与构建重新生成。

## 规则与证据模型

规则记录至少包含 `kind`、规范化值、选项、全部来源 ID、原始规则定位和应用目标。`DOMAIN` 与 `DOMAIN-SUFFIX` 不是同一条；IP 规则保留地址族、网段和 `no-resolve`；通配符或关键字保留原生含义。无法转换时明确失败或按声明只进入支持的目标，不能剪去修饰符后继续。

保护与审核结果独立记录为保留、剔除、待审核或失败，并附策略 ID、原因及来源。不把“解析成功”“某来源独有”“DNS 可解析”直接解释为广告有效性。

报告保留当前 `sources`、`counts`、`output_sha256` 等字段，扩展时增加 schema 版本。未来从单脚本拆成多个模块后，发布快照须包含全部必要源码、配置和许可，使保存输入后的构建仍可复现；不能只复制旧的 `build.py`。

## 兼容与迁移约束

- `dist` 中现有文件名与订阅 URL 保留；切换稳定发布方式时不要求用户更换 URL。
- 候选构建用独立目录，不能把本地试验结果覆盖为稳定基准。
- 文档规划完成后，当前自动直发行为仍然存在；实际切换须由后续工作流变更完成。
- 关键策略及发布变更分阶段验收；不同时大改解析语义与发布机制，方便定位差异。
