# 验证与保护设计

状态：待实施。当前已有来源核对、格式检查和构建回归；本页的业务保护、风险报告与持续内核测试尚未进入生产流程。当前事实见 [验证记录](../VERIFICATION.md)，任务见 [实施计划](roadmap.md)。

## 验证分层

| 层次 | 要回答的问题 | 当前情况 | 目标验收 |
| --- | --- | --- | --- |
| 来源与输入 | 下载的是哪个文件、是否完整 | 已有固定提交、哈希、最低条数与骤减检查 | 保留完整输入、配置、源码与许可 |
| 转换与合并 | 匹配范围和放行语义是否保留 | 已有解析与构建回归 | 扩展冲突、父子域、原生模式的边界测试 |
| 业务保护 | 正常业务是否被重新引入的规则影响 | 保护策略未实现 | 全来源统一保护，有依据、有处理报告 |
| 实际内核 | 两种客户端实际如何处理 | 曾本地测试，未持续运行 | 每个可晋升候选通过固定内核回归 |
| 设备场景 | 登录、播放等功能是否正常 | 未完成场景验收 | 固定候选在设备上验证并留下记录 |

不把某层通过描述为其他层通过。上游声称有效只能作为证据线索；本项目结论须限定输入版本、环境和场景。

## 三类配置分别负责什么

| 配置 | 作用 | 不适合承担的用途 |
| --- | --- | --- |
| `blocklist.txt`（已有） | 明确增加拦截规则 | 自动绕过业务保护或上游放行 |
| `allowlist.txt`（已有） | 明确放行具体域名或后缀 | 表达父域全放行但其中若干广告子域仍拦截 |
| `protection.json`（待建） | 保护范围、可保留的广告例外及依据 | 把上游名单未经审查直接认定为本项目安全结论 |

目标保护配置示例，不是当前可用配置：

```json
{
  "schema_version": 1,
  "policies": [
    {
      "id": "novel-video",
      "domain": "qznovelvod.com",
      "scope": "suffix",
      "permitted_block_rules": [
        {"domain": "v11-reading-ad.qznovelvod.com", "scope": "suffix"}
      ],
      "reason": "保护正片视频，只保留已确认的广告子域",
      "evidence": ["上游固定版本说明；本项目待补实机验证"],
      "evidence_level": "upstream-reference",
      "reviewed_on": "2026-11-26"
    }
  ]
}
```

示例广告子域不构成完整名单或实机有效性声明。首批策略先审查 Home DNS 的保护候选与例外，并加入登录、图片、正片和基础网络场景。`apple.com` 等大范围保护必须评估功能与过滤目标，不能整表照搬。

## 保护算法与冲突处理

先合并全部来源与本地拦截，再应用同一套保护策略；不能只处理某个来源的输入。保留原始快照，处理只作用于目标输出并完整记账。

1. 域名规则的匹配集合完全落在保护范围内：若不属于已确认广告例外，则从输出剔除；报告列出全部来源与策略 ID。
2. 明确的可保留广告规则：只允许保留已经存在的对应拦截规则，不自动创造新规则，也不扩大其范围。首阶段例外只用精确域名或有明确边界的后缀，不自动展开正则或猜测域名。
3. 上游后缀规则覆盖了更大的父域、只与保护范围部分重叠：不可只删除一个子项后声称已保护，也不可擅自扩大放行；停止可用候选发布并报告待审核冲突。
4. 关键字、通配符或 IP 网段无法静态证明与保护范围不相交：报告不确定性，相关保护场景必须通过实际内核检查；无法界定影响的项需要审核。域名白名单不能保证绕过所有 IP 层阻断。
5. 多条保护策略重叠或广告例外与明确白名单冲突：停止发布并要求修正配置；不靠文件顺序决定。明确白名单或原生例外不会被广告例外暗中覆盖。
6. 本地新增拦截若违反已确认保护，视作配置错误；本地优先不等于允许绕过保护。

可保留的广告例外须位于对应保护范围内。若其预期拦截被其他放行规则覆盖，回归应失败并显示冲突；不通过增加 `$important` 等方式强行压过放行。

Home DNS 模式主要通过构建时筛选域名拦截项实现，不能直接用 `@@||qznovelvod.com^` 替代。本项目对保留的模式、IP、父域范围还要补上交叉验证。

## 变更分析与审核条件

比较对象使用最后一次稳定版，不使用上一轮未晋升候选代替。对于同来源变化，同时提供上一候选对照以帮助排查，但不能因此忽略相对稳定版的累计变化。首版没有稳定基准时进入人工建基准流程。

每轮输出新增、删除、来源重叠、放行变化、策略处理、可疑匹配范围变化、历史场景结果及未完成项。逐条来源定位应能回答哪几家带入、为何留下或删除。

| 情况 | 结果 |
| --- | --- |
| 必需来源下载失败、未知语法、快照异常、最低条数或现有骤减检查失败 | 失败，不替换可用候选或稳定订阅 |
| 明确位于保护范围的非例外域名拦截 | 按策略剔除并记录；有效性测试再确认 |
| 保护冲突无法按既定语义处理、预期放行或拦截回归失败 | 失败；问题报告供复核 |
| 新增或扩大关键字、通配符、IP 范围，精确匹配转后缀，白名单范围变化 | 待审核，不晋升稳定版 |
| 相对稳定版单来源新增或删除比例超过初始提示阈值 5% | 待审核；阈值可依据历史调整，不能只看比例 |
| 公网 DNS 超时、地理差异、限流 | 未知，不当作通过或广告属性判断依据 |

待审核与失败分开：待审核结果可以保存为诊断产物，并在明确标记后进入试验候选；它不能冒充全部检查通过。存在保护冲突或测试失败时不更新可订阅候选，只保存报告。批准必须绑定候选版本及明确审核项。

## 持续测试

`tests/scenarios.json` 计划记录用例 ID、客户端、域名、必要的目标 IP、预期拦截/通过、原因、证据与必测等级。必测场景至少包括：

- 已确认广告接口与其正常业务对应项。
- 视频主域下的正常播放域与已确认广告子域。
- 登录、图片、风控、基础网络及历史误拦。
- 精确规则之外的子域、相似域名，域名大小写和结尾点。
- 原生白名单覆盖、父子域重叠、IP 与域名交叉、关键字或通配符影响。

静态测试用于语义边界、来源完整和异常路径；最终匹配以实际内核结果为准。固定官方 Mihomo 和 AdGuard Home 版本及下载 SHA-256，CI 使用 Linux，先比较与历史 macOS 验证的差异。升级内核单独跑兼容回归。

内核使用临时目录、回环高位端口和受控上游服务，不改系统 DNS，不安装服务。检查 Mihomo 拒绝、放行后继续正常分流，AdGuard 原生例外及 UDP DNS 实际响应。A/AAAA 都应覆盖，阻断断言尊重配置的 `0.0.0.0`、`::` 或 NXDOMAIN 模式。

没有安装内核或场景执行失败属于未完成，不能静默跳过并允许晋升。测试进程、端口和临时文件在成功与失败时都要清理。

## 设备验收与证据

候选固定到提交后，在单台设备完成约定场景；24–48 小时可作为观察窗口，但不是自动通过条件。需实际执行登录、正片播放、图片加载，以及使用者依赖的支付、推送或更新功能。只观察没有告警不等于广告过滤或业务正常已经验证。

记录候选 ID、文件哈希、设备与内核版本、App 版本、场景、命中规则、临时放行前后结果及未执行项。只保存最小必要的脱敏证据，不自动收集或公开家庭全量 DNS 日志。无设备或未完成场景时保留待验收状态。

场景完成与审核结果构成晋升依据。紧急修复也应记录豁免范围、原因、操作者和后续补验收项，不能补写成完整测试通过。
