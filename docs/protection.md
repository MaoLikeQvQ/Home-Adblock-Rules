# 业务保护与规则风险

## 配置职责

| 配置 | 用途 |
| --- | --- |
| `config/blocklist.txt` | 手动补充拦截，不得绕过已确认保护 |
| `config/allowlist.txt` | 明确放行精确域名或后缀，与上游原生例外共同生效 |
| `config/protection.json` | 定义业务保护范围、可保留广告例外和证据 |
| `config/validation.json` | 变化审核阈值、按平台固定的内核 URL/版本/SHA-256 |

保护策略在所有来源合并之后统一执行。配置严格校验，未知字段、重复 ID、非法范围和相互矛盾的策略会报错。

## 保护语义

- `scope: exact` 只保护该域名；`suffix` 包含本域和标签边界内的所有子域。
- 拦截范围完全落入保护、又不是允许例外时，从输出剔除并保留全部来源。
- `permitted_block_rules` 只允许保留已经存在且类型和值等价的广告规则，不创造或扩大规则。
- 更大父域的拦截只与保护部分重叠，无法无损处理时构建失败，不擅自整体放行或删除。
- 策略重叠、例外越界、例外与明确放行冲突、本地规则违反保护均明确失败。
- 禁用策略只表示待确认，不提供保护。`evidence_level` 表示证据来源，不代表本项目已完成实机验证。

父域保护且广告子域仍需拦截，应在构建阶段筛选黑名单，不能简单输出父域全局放行。例如 `@@||qznovelvod.com^` 会同时放过其中的广告子域。

## 已采纳的保护

依据 [Home DNS 固定版本白名单](https://github.com/abclq/home-dns-adblock/blob/27a0a29c9941759662f48b78c985d0273caaa023/config/whitelist.txt) 和 [业务域名说明](https://github.com/abclq/home-dns-adblock/blob/27a0a29c9941759662f48b78c985d0273caaa023/docs/domain-list.md)，当前采纳以下三项后缀保护：

| 域名 | 采纳原因 | 证据边界 |
| --- | --- | --- |
| `gecko.snssdk.com` | 上游业务资源下发保护 | 受控内核通过，真实 App 待验收 |
| `is.snssdk.com` | 上游风控业务保护 | 受控内核通过，真实 App 待验收 |
| `tz.sec.xiaomi.com` | 上游小米系统服务保护 | 受控内核通过，路由器/设备待验收 |

其他视频、图片、CDN、Apple 等范围没有整表照搬。特别是 `qznovelvod.com` 的广告例外需完整核对，宽泛主域保护也可能放过原有广告或遥测。新增策略须保存明确依据和回归，实际配置以 `protection.json` 为准。

## 风险审查

在已测试的固定输入上，4 条 Mihomo 关键字和 4 条 AdGuard 通配规则可与三个保护后缀产生交集。工具会生成合法合成子域并验证其匹配，不能因为保护主域不含关键词就声称整个后缀都安全。另有 13 条 IP 规则需要路由器目标地址和有效路由证据；`no-resolve` 不保证不会影响已有目标 IP 的连接。

这 21 项继续待审核，不因少量场景通过就自动批准。具体规则、来源、行号和样例由每轮候选的 `decisions.json`、`validation.json`、`VALIDATION.md` 生成，不在源码文档中复制长期易过期的明细表。

相对最后稳定版，来源数量变化、白名单变化、关键字/模式/IP 新增、匹配范围扩大等产生审核项。新增/删除初始提示阈值为 5%；最低条数和默认 35% 骤减检查仍作为失败条件。没有稳定基准时需要 bootstrap 审查，不能默认为通过。

来源哈希只证明文件身份；DNS 可解析、规则独有、合成子域命中均不能单独证明真实 App 广告属性或业务影响。处理误拦时应做窄范围放行对照，证实后更新策略、重新构建和验收。
